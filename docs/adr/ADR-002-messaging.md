# ADR-002 — Messaging and reliable publication
Status: Accepted design; local PostgreSQL primitives and an Azure Event Hubs outbox publisher are implemented in code. Azure runtime, consumer and cloud verification remain pending.

**Decision:** PostgreSQL is the canonical admission boundary. It assigns a positive per-match `canonicalRevision` and commits canonical changes plus outbox rows in the same transaction. Only the outbox dispatcher publishes admitted canonical telemetry to Event Hubs, partitioned by matchId and carrying the assigned revision. Raw source candidates do not use the canonical envelope or telemetry channel. Service Bus transports durable background commands (explanation, recap, exports, recovery). The dispatcher publishes idempotently with stable message IDs.

**Consequences:** At-least-once delivery is expected. Consumers deduplicate using stable message IDs, bound retries and isolate poison messages. EP04-S03 adds a PostgreSQL transaction port that binds aggregate updates to the persisted predecessor projection and immutable source identity, an aggregate-owned in-process mutation lease across preview/persist/apply, leased dispatcher state with renewal during active publish, a same-database inbox transaction, and local .NET metrics instruments. The Azure-only EventWorker now leases PostgreSQL outbox rows, validates the shared `ProjectionPublishedV1` envelope and publishes its original JSON to Event Hubs with the stable outbox ID and `matchId` partition key using managed identity. The lease also blocks direct aggregate mutation and snapshots until the write finishes; the PostgreSQL advisory lock remains necessary for cross-process serialization. Lease renewal cancels publisher work when the database lease is lost but is not an external fencing token; an adapter must honor cancellation and consumers must deduplicate. Schema v11 adds a PostgreSQL partition-cursor store that records Event Hubs offset, broker sequence number, last match/message and canonical sequence after a consumer's inbox/effect commit. It refuses gaps, backwards movement and conflicting duplicate positions. This database cursor is separate from the Event Hubs SDK checkpoint call; no broker consumer is wired to invoke either path yet. The worker uses managed identity and verified TLS for Azure PostgreSQL; password-based connection strings are rejected. No Event Hubs consumer, hosted checkpoint/order enforcement, Service Bus adapter, exporter, Azure runtime or cloud connection has been verified. Cross-system exactly-once delivery is not claimed.
