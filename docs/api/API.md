# PitchMind — Consolidated API Contract and Implementation Registry
**Current baseline:** fail-closed v1 match routes with EP01-S04 typed contracts, a guarded LOCAL runtime profile, and typed Analyst request validation/body-size/rate-limit behavior verified locally on 2026-10-14. **Design target:** proposed `v1` extension, **NOT implemented** unless explicitly marked `CURRENT`. Source files: `src/PitchMind.Api/Program.cs`, `src/PitchMind.Contracts/V1/MatchContracts.cs`, `frontend/src/api.ts`. No missing API is assumed working because it appears here.

## Principles
Public route prefix `/api/v1`; JSON camelCase; timestamps match selected-time contract, period/added-time explicit when supported; football data exclusively from versioned synthetic JSON/authoritative projections; `X-Correlation-ID` returned in every response. All read responses include `provenance`, `sourceVersion/hash`, `canonicalRevision`, `schemaVersion` and `asOf` **once implemented**. Never leak events later than `atSeconds`. JWT with scoped roles for nonpublic and mutation routes. Bounded queries, stable cursor pagination, ProblemDetails on errors. For the current offline fixture, `atSeconds` is bounded by the returned `durationSeconds` (currently 0..5400); the fixture response also carries `halfTimeSeconds`, `pitchLengthMetres` and `pitchWidthMetres` for replay and pitch rendering. Revisions with `ETag` / `If-None-Match` proposed.

Only `/api/health` and `/health` currently return successful process health. Match routes are mapped but fail closed because the synthetic scenario generator was moved out of production assemblies and no canonical feed adapter is registered. Ordinary match reads and valid Analyst requests return typed `503 MATCH_DATA_UNAVAILABLE`; the analyst endpoint returns typed `429 RATE_LIMITED` after its configured quota. The Analyst handler validates JSON media type, malformed JSON, required fields, `atSeconds` bounds and the audience enum. Request bodies above the 4096-byte cap return typed `413 REQUEST_TOO_LARGE`, including chunked requests with no declared content length; unsupported content type returns typed `415 UNSUPPORTED_MEDIA_TYPE`. API problem responses include the v1 error code and correlation ID and do not expose framework exception messages. Successful `/api/v1` responses include `X-Contract-Version: 1`; all responses include `X-Correlation-ID`. The previous test-only fixture is not exposed as canonical data. C# DTOs remain in `PitchMind.Contracts.V1`; the React consumer still loads only through `request()` and has no production fallback facts. Startup accepts `Runtime:Profile=local` only with the `Development` environment and accepts the `azure` profile in supported host environments; the in-memory event store is registered only with the local profile. These profile checks do not replace authentication, identity, or Azure adapter configuration.

The current `POST /api/v1/matches/{matchId}/analyst` body is `{ "insightId": "…", "atSeconds": 0, "audience": "fan" }`; `audience` is optional and defaults to no audience-specific response. `insightId` must be a nonempty string, `atSeconds` an integer from 0 through 5400 inclusive, and `audience`, when supplied, exactly `fan` or `analyst`. Missing or non-integer time is `400 INVALID_REQUEST`; an integer outside the supported range is `400 INVALID_TIME`. A valid request still returns unavailable until a canonical read port exists; the API does not fabricate an explanation.

The current v1 DTO property names and representative JSON types are pinned by `PitchMind.Contracts.Tests`. The selected-time state DTO carries optional `competitionId`, `competitionRulesVersion` and `maximumSubstituteReentriesPerPlayer` fields so consumers can identify the competition context used by the aggregate; null means no competition rules were supplied. `scripts/api-contract-integration.py` runs the live HTTP route, typed error-envelope, Analyst validation/body-size, and rate-limit checks against a fresh loopback API process; local validation and the Azure Pipelines .NET job invoke it after the Release build. This verifies the current fail-closed prototype contract and does not establish a canonical read path or a hosted pipeline run. `MatchContractMappings` maps application read models to public response DTOs when canonical read-port routes are implemented. The React test fetch stubs and C# golden fixture generator are test-only; production UI data is loaded through `request()` and never falls back to those examples.

EP04-S04 adds an internal `GetMatchAtQueryService` backed by `PostgresMatchProjectionReader`. It returns a point-in-time state and evidence-bounded replay result from PostgreSQL, pinned by selected clock, canonical admission revision and algorithm/detector version. The query is not registered in API composition and creates no public HTTP contract. All match routes above therefore remain unavailable; this addition does not enable a canonical public read path or frontend scrubbing. See the EP04-S04 work packet and PostgreSQL replay evidence for the internal contract and its test limits.

The mapped insight DTO includes sourceVersion, sourceSha256, provenance, nullable 64-bit canonicalRevision, selectedTimeSeconds, throughSequence, policyStatus, publishable, and detector conditions. The offline `sourceSha256` is the SHA-256 fingerprint of the exact serialized synthetic fixture; the revision-pinned PostgreSQL replay uses the validated canonical projection source hash. Its route remains unavailable in the current API composition. The offline candidate returns classification simulated, policyStatus unapproved-demo, publishable false, provenance synthetic, and canonicalRevision null; this is not a canonical football fact, football approval, or an implementation of the candidate Manu–Liverpool feed. The detector only evaluates the selected-time prefix and reports the highest included event sequence. Do not relabel this response as evidence-supported, approved, or production-ready.

The current candidate insight also includes nullable `context` with `schemaVersion: "tactical-context-v1"`: selected-time scoreline, pressing team's `home`/`away` role, signed active-player difference for that team, reducer match phase, and the observed opponent transition from in-possession at the trigger to defending after the regain. Both offline and internal PostgreSQL replay paths derive it from the same selected-time event prefix used for the score projection. It does not infer a low block, a decision to concede possession, intent, control, or comparative tactical quality. Context is null if a selected-time state is unavailable; consumers must not substitute inferred values. This versioned field is not evidence of Product Owner or football approval.

Current insights also carry a typed `evidenceGraph` with claim, event, frame, and metric nodes; truth classes include `fact`, `derivation`, `pattern`, `interpretation`, and `hypothesis`; edges use `precedes` and `derived_from`. The graph and every node carry the same SHA-256 fingerprint of the exact serialized synthetic fixture. Each condition has an ID, observed evidence, source-node IDs, optional threshold, and an exclusion reason when it fails; the graph also carries explicit uncertainty. The offline graph marks source event/frame nodes as facts only within the synthetic fixture; graph provenance remains `synthetic`, canonical revision is null, and the pattern claim is not publishable. A metric derivation node records selected-time context and links to selected-prefix score, phase, detector-sequence events, and a source-hash-pinned active-roster node derived from `MatchState.Players[Active=true]`. A selected-context condition lists the same source nodes, so the score, phase, pressing-team role, possession transition and active-player difference have explicit graph lineage. Its `numericValue` is the signed active-player difference for the pressing team and its `unit` is `active-players`; it is reducer-derived context, not a provider performance metric. No player-performance metric nodes are emitted because none are validated. The builder rejects unresolved IDs and evidence outside the selected-time prefix. The validator refuses publishable status unless policy is approved and evidence is from a revisioned canonical source, all conditions pass, and source references resolve.

## Envelope and DTO contracts — proposed additions
`MatchTimeContext`: `{matchId,mode:'liveHead'|'selectedTime',selectedElapsedMs,period,contextRevision,canonicalRevision}`.
`Snapshot`: `{matchId,asOfElapsedMs,period,score:{home,away},status,activePlayers,frameRef?,canonicalRevision,provenance,sourceHash,coverage}`.
`InsightSummary`: `{insightId,matchId,asOfElapsedMs,truthClass,algorithmVersion,summary,conditionResults,evidenceRefs,limitations,revision}`.
`EvidenceRef`: `{kind:'event'|'frame'|'metric'|'condition',id,matchId,elapsedMs,sourceVersion,algorithmVersion,canonicalRevision}`.
`ValidatedExplanation`: `{answerId,selectedTime,audience,source:'foundry-validated'|'deterministic-fallback',text,claims:[{text,evidenceIds}],limitations,revision,modelVersion?,traceId}`.
`RealtimeCursor`: `{kind:'matchUpdated',matchId,canonicalRevision,lastSequence,serverUtc,schemaVersion}`; **payload does not carry canonical truth**.
`EventEnvelopeV1` and `TrackingFrameV1` are post-admission canonical transport contracts in [telemetry contracts v1](../data/TELEMETRY-CONTRACTS-V1.md); each requires a positive store-assigned `canonicalRevision`, distinct from `schemaVersion`. Non-negative values serialized into .NET `long` fields are bounded by `Int64.MaxValue` in the schemas. Decimal schema rules constrain supported scale and coefficient; each decimal DTO member uses `ExactDecimalJsonConverter` so default `System.Text.Json` deserialization rejects values that would overflow or lose precision. Coordinate schemas also require non-negative values while runtime validation enforces unit-specific pitch bounds. Identity strings are bounded to 128 characters, source labels/outcomes/status fields to 256, source hashes to exactly 64 lowercase hexadecimal characters, and source timestamps to 64 characters. Source hash, provenance, explicit coordinate semantics and period are mandatory where applicable. Substitutions require two distinct participant IDs, enforced by the runtime validator. Pre-admission source candidates have no canonical revision and cannot validate or publish as these DTOs. Optional event locations require their declared pitch coordinate system and the direction for the event's team. Candidate-feed mapping remains separately governed by the [simulation feed contract](../data/SIMULATION-FEED-CONTRACT.md).

## Synchronization and pagination example
1. UI chooses selected 55:08; all page queries add `atSeconds=3308` and match/contract revision. A 55:09 goal, its tactical insight, evidence and AI explanation cannot appear in this view.
2. Live cursor `lastSequence=N+1` arrives while user scrubs; show "New match update — return to live" but keep `SelectedTime`; fetch on explicit click only.
3. Historical snapshot `revision=R` and evidence `revision=R` must match. On 409 revision conflict, refetch atomic snapshot, invalidate stale queries by clientContextRevision and rerender after new evidence resolves.
4. Pagination: stable `(matchId,revision,sequence)` cursor; max proposed 100 events per page; endpoint rejects excessive unbounded requests with 400 or 413; complete data not duplicated/omitted across pages.

## Errors, security and evolution
`application/problem+json` with `type,title,status,detail,instance,correlationId` and typed `code`: `INVALID_TIME`, `SCHEMA_UNSUPPORTED`, `EVIDENCE_MISSING`, `REVISION_CONFLICT`, `INSUFFICIENT_TRACKING`, `UNAUTHORIZED`, `FORBIDDEN`, `RATE_LIMITED`, `REQUEST_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `DEPENDENCY_UNAVAILABLE`. Current verified validation, evidence, size and rate-limit failures use `INVALID_REQUEST`, `EVIDENCE_MISSING`, `REQUEST_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE` and `RATE_LIMITED`. Use 400 for validation, 401 unauthenticated, 403 denied, 404 inaccessible/unknown, 409 revision/conflict, 413 oversized, 415 unsupported media type, 422 semantically invalid envelope, 429 exhausted rate, 503 unavailable. No sensitive provider payload in error detail.
Authentication target: Entra/OIDC auth code+PKCE; strong JWT issuer/audience/expiration signing key validation; scoped roles fan/analyst/admin; anonymous access only an owner-approved synthetic demo profile. Mutations require appropriate role, anti-CSRF where using cookies, replay/export quotas, strict CORS/CSP, no client-side Foundry credentials.
API version `v1` is additive compatible. Breaking schema/meaning change = `v2` and migration plan. Generated OpenAPI document and typed React/.NET contract tests should be published in CI. Every newly implemented endpoint must update this file and receive positive, negative, historical, authorization, rate-limit, failure and cursor tests **in the same PR**.

The [generated candidate field dictionary](../data/MANU-LIV-CANDIDATE-FIELD-DICTIONARY.md) records JSON structure only. The owner confirmed synthetic provenance and redistribution permission, but clock policy, coordinate units/orientation, player metric meaning, canonical event mappings and football realism remain unverified. The old generator is test-only; ordinary match reads return `503 MATCH_DATA_UNAVAILABLE` (the analyst endpoint may return `429` when rate-limited before its handler) until route composition is replaced with a canonical, revisioned PostgreSQL-backed read port and the input gates pass. Adapter and API changes need versioned contracts and regression tests; missing coverage remains unavailable.
