# Architecture review — 2026-10-08

**Scope:** C4 L1 system context, L2 containers, L3 components, deployment/trust boundaries, football LLD, ADR-001..008, execution register, API, representative application/domain/infrastructure/frontend code and documented DEV deployment evidence. **Method:** static repository/document review; no new builds, Azure deployment, network probes or pipeline executions performed. Findings are observations/recommendations, not proof of a new defect or an achieved release gate.

## Assessment

The evidence-first hexagonal architecture is appropriate for an event-driven football product. The primary risk is the **target-vs-executable gap**, not the service selection. Every design or planning artifact must identify its verification state. The isolated local/offline synthetic read path is valuable for experience validation but cannot establish the canonical cloud path.

## Architecture clarification actions

1. Revise C4 L2 to show **CURRENT** synthetic path versus **TARGET** canonical path distinctly, with optional Front Door and a direct-ingress alternative.
2. Revise C4 L3 to distinguish pure football components, application ports, infrastructure adapters, transactional outbox and evidence claim verification; label adapters unimplemented unless linked to code/tests.
3. In deployment C4, include credential and network trust boundaries, separate worker/agent identities and network compatibility assumptions, not decorative links.
4. Document contract subjects: match event schema, coordinate/period/time, tracking quality, evidence IDs, revision and API selected time, outbox/inbox, SignalR cursor, AI truth classes.
5. Require a per-story architecture delta, ownership, rollback/rebuild plan and **proof links** before changing design status from target to implemented or verified.

## Decision

**Conditional architectural endorsement for continued LOCAL engineering**, not approval for canonical Azure DEV rollout or production readiness. The governing documents are the C4/LLD, ADRs, API, backlog and execution evidence; update them in the same PR as any actual architectural change. Independent security, football and release reviewers may block unsafe changes with documented reasons.
