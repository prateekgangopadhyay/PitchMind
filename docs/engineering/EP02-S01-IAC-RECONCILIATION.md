# EP02-S01 — IaC and MVP dependency reconciliation

**Story:** EP02-S01, P0. **Purpose:** reconcile the Bicep foundation with the deployable MVP topology and identify dependencies that are not yet safe to assume available. **Review date:** 2026-10-09.

## Evidence boundary

This is a repository and prior-evidence review, not a new Azure inventory. The observed state below is taken from [the dated DEV execution record](evidence/2026-10-08-DEV-DEPLOYMENT.md), which records a read-only inventory of `rg-pitchmind-dev-001` in `centralindia`, followed by a separately recorded deployment and smoke of the bounded offline API. No Azure command, what-if, provisioning, or deployment was run for this reconciliation. Historical evidence is not a fresh assertion of current state.

The acceptance criterion is a resource-by-resource provisioned/deferred/blocking matrix, with no inference that a disabled-public-access service is reachable. The labels mean:

- **Provisioned (observed):** prior evidence reports the resource present or a successful deployment. This does not imply canonical workload integration.
- **Declared only / blocked:** Bicep contains a resource or design intent, but the evidence does not show it deployed or usable.
- **Deferred:** intentionally outside the MVP slice, optional, or awaiting a later epic.
- **Blocking:** required for the canonical Azure product path and not proven available. A disabled public endpoint without verified private connectivity is treated as inaccessible.

## Dependency order and release conditions

1. **Resolve topology before adding workloads:** choose supported ACA VNet integration and subnet layout; confirm it does not conflict with the existing PostgreSQL delegated and private-endpoint subnets. Identify outbound routing and private DNS ownership.
2. **Establish the canonical store:** finish Flexible Server private networking and DNS, then define migration/runtime identities and schema rollout/rollback. Do not route canonical state to memory, Storage, Redis, Event Hubs, or Service Bus.
3. **Wire private dependencies:** the isolated candidate now declares Blob, Key Vault and Event Hubs namespace private endpoints and DNS zone groups. Review existing target IDs, DNS ownership, public access policy, Service Bus networking and address overlap. Test resolution and TCP/TLS/application authentication from the actual ACA consumer identity and network before calling any path usable.
4. **Wire workload identities and ingestion:** use separate least-privilege identities for API, feeder, event worker, agent, migrations and CI. Preserve Event Hubs partition/order semantics and PostgreSQL transactional/idempotent writes. No secret value belongs in source or parameters.
5. **Add telemetry and spend limits:** define useful health/lag/failure measures, diagnostics/alerts, monthly budget and teardown. Current broad monthly ranges in [COST-ASSUMPTIONS.md](../cost/COST-ASSUMPTIONS.md) are illustrative, not a dated regional quote or per-resource estimate.
6. **Only then prepare a change-specific deployment:** compile IaC, inspect an authorized read-only what-if, review cost/security/deletes and rollback. Provisioning, image publishing, role changes and DEV deployment remain separate and require explicit owner approval for the exact change.
