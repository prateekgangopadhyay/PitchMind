# EP04-S04 version-pinned point-in-time replay — local evidence

## Scope and revision

Code commit `2df5bfa8bbccd911526ada584d043dcc853faf59` (tree `9b19f1fef2b4472bc2f8c656d6ffb3a460c86d54`) on `codex/ep04-s04-versioned-point-in-time-replay`, based on the draft EP04-S03 follow-up branch from PR #213. This implements a version-pinned **offline synthetic fixture** replay envelope. It is not canonical PostgreSQL replay and does not use the candidate Manchester United–Liverpool JSON.

`SyntheticMatchService.ReplayAt` bundles the selected event-prefix projection, events, and insights; returns fixture version/seed, replay algorithm and detector versions, a serialized-fixture content SHA-256, and output SHA-256; and rejects unsupported caller pins. The API route is `GET /api/v1/matches/{matchId}/replay?atSeconds=N`. `canonicalRevision` is deliberately null and `executionMode` is `offline-synthetic-fixture`.

## Limits and remaining work

The API's current runtime remains `SyntheticMatchService` and `InMemoryMatchEventStore`, not PostgreSQL. The canonical event payload persisted by the current store contains `MatchEvent` only; it omits the `SimulationEvent` team/player/action/outcome context required to reconstruct scored state and participants. The match metadata schema also has no immutable roster/replay-seed record. Durable PostgreSQL replay, candidate-feed import/mapping, source semantics/football review, authentication, exact-head independent review, EP04-S03 dependency verification, Product Owner acceptance, and any cloud deployment remain unverified. No Azure resources were touched.
