## Scope

The API now accepts Entra bearer tokens from SignalR browser transports through `access_token` only on the exact `/hubs/matches` request path. The opt-in Development header adapter also accepts bounded `pmdev.v1` browser bearer credentials for local testing. Query credentials are rejected on API routes, hub negotiation routes, other hubs, duplicate values, and empty values. The local token is unsigned and is not an Azure identity mechanism. ADR-010 and the API contract document these boundaries and the requirement to redact hub query tokens from future proxy/host request logs.

This is only the API authentication boundary. It does not wire the React SignalR client, prove a connected-browser reconnect/backfill journey, validate Entra against a real tenant, or accept EP06-S03.
