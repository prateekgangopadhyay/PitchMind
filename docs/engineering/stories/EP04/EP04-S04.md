## Local implementation contract (EP04-S04)
`IMatchProjectionReader.GetAtAsync(matchId, selectedSeconds, upToCanonicalRevision, algorithmVersion)` returns the latest immutable projection with `as_of_clock_seconds <= selectedSeconds`, `canonical_revision <= upToCanonicalRevision`, and the exact requested algorithm version. Canonical admission revision and projection revision are returned separately; selection orders by selected clock, sequence, canonical revision, then projection revision descending. An absent history returns `null`. A returned state is deserialized, re-hashed, and checked against its persisted match ID, sequence, and clock before use. `ReadEventsAtAsync` re-fetches the exact match/canonical/projection revision from PostgreSQL and validates its sequence, clock, algorithm/source metadata and state hash before using its persisted sequence and canonical revision as the event-window ceiling; it also validates each event against its indexed time/period and rejects a non-contiguous prefix. Both methods enforce the current prototype range 0..5400 seconds.

The derived replay uses `ReadReplaySnapshotAtAsync`, which selects projection, match source identity, event envelopes, replay seed/context and bounded tracking frames from one SQL statement snapshot. The context fixture version, provenance and pitch dimensions must match the registered match row; each tracking payload ID and clock must match its indexed row. Same-clock frames remain sequence-ordered. The detector requires one unambiguous press-arrival frame, but permits extra same-clock samples for other evidence events and includes those frame IDs in the derived evidence.

`CanonicalUpdate` retains the exact `SimulationEvent` applied by the aggregate. Schema v6 persists this source envelope in `match_events.source_event_json` and stores a versioned `match-replay-seed-v1` initial roster/team/provenance record in `matches.replay_seed_json`; v7 adds nullable `matches.replay_context_json`. Old rows remain NULL rather than being backfilled with inferred names, match timing, pitch orientation or detector inputs. `MatchReplayContext` binds fixture version, team names, duration, halftime, pitch dimensions, `metres-v1`, explicit coordinate convention and provenance to immutable match metadata. `GetMatchAtQueryService` consumes the single-snapshot projection/event/context/frame read, replays the seed/envelopes through a fresh pure `MatchAggregate`, and compares the canonical serialized state digest with the stored projection digest. It checks replay context against the registered fixture version, provenance and pitch dimensions, and checks tracking payload IDs against indexed frame IDs. The selected tracking frames are bounded by canonical revision and elapsed time; the service checks source hash, sequence, period, coordinate version, team mapping and active roster at each frame time. It runs exactly the requested `press-sequence-v1` detector over the selected input prefix. The result carries a replay-input digest and a derived-output digest that includes selected time, canonical revision, as-of sequence and detector version. Missing seed/context/envelopes/frames, unsupported detector or coordinate version, malformed/noncontiguous input, future leakage and digest mismatch fail closed. Derived output digests are computed on read and are not persisted as canonical facts. The Application query is not registered as an HTTP route.

Application deterministic replay tests use the approved first-party fictional synthetic fixture: at 3308 no derived press insight is emitted; at 3309 the seven-event evidence-linked pattern appears, and repeated reads produce identical serialized insight, input digest and output digest. Extra same-second tracking evidence does not suppress the pattern. PostgreSQL integration seeds frames across the pattern, verifies the positive derived result, checks source-context and frame-ID corruption fail closed, and confirms the selected-time cut excludes later frames; repeated reads have identical input/output hashes. Migration coverage asserts legacy replay seed/context remain NULL. Tests also pin an unsupported detector version as an explicit failure. These local tests do not certify candidate Manu-Liv semantics, public API/auth, UI scrubbing, persisted derived insight lineage, or cloud integration. The candidate feed remains unused because its data dictionary and canonical mapping are unapproved. The query remains internal and is not mapped to an HTTP route.
