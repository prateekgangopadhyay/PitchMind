## Current implementation delta — version-pinned offline replay envelope

The offline `SyntheticMatchService` replays an explicitly supplied synthetic fixture and selects state, frames, evidence and detector output by elapsed match seconds. `ReplayAt` returns state, source-ordered events and insights with fixture version/seed, replay algorithm version, detector version, fixture-content fingerprint, and output fingerprint. Optional pins reject a different fixture, seed, algorithm or input hash. The response DTO can represent `executionMode=offline-synthetic-fixture` and `canonicalRevision=null`; **the current API does not expose an HTTP replay route**. Mainline deliberately keeps match reads fail-closed until a canonical PostgreSQL read port is available.

The input fingerprint describes only the fixture object supplied to this service. It is not the raw candidate-feed SHA, approved feed manifest, provider source identity, canonical PostgreSQL revision, or evidence that the candidate feed was admitted. Canonical replay remains blocked until the durable envelope preserves the simulation event's team/player/action/outcome fields and a versioned immutable roster/replay seed is persisted; `match_events.payload` currently contains only `MatchEvent`, which cannot reconstruct scoring team or participants. This is a service-level offline code slice, not durable replay, public API implementation, or story acceptance.
