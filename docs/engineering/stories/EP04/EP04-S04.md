## Current implementation delta — version-pinned offline replay envelope

The existing offline `SyntheticMatchService` already replays the event prefix and selects state, frames, evidence and detector output by elapsed match seconds. The missing current-path contract was one response that binds those outputs to the same selected time and versions. `ReplayAt` now returns state, source-ordered events and insights with fixture version/seed, replay algorithm version, detector version, fixture-content fingerprint, and output fingerprint. Optional query pins reject a different fixture, seed, algorithm or input hash. API route: `GET /api/v1/matches/{matchId}/replay?atSeconds=N` with optional version/hash pins. The response states `executionMode=offline-synthetic-fixture` and `canonicalRevision=null`.

The input fingerprint describes the fixture object loaded by the offline demo. It is not the raw candidate-feed SHA, approved feed manifest, provider source identity, canonical PostgreSQL revision, or evidence that the candidate feed was admitted. The route does not read PostgreSQL. Canonical replay remains blocked until the durable envelope preserves the simulation event's team/player/action/outcome fields and a versioned immutable roster/replay seed is persisted; `match_events.payload` currently contains only `MatchEvent`, which cannot reconstruct scoring team or participants. No durable replay or story acceptance is claimed.
