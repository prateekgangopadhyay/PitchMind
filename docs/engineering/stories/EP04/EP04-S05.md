This verifies local input/version isolation only; it does not implement a persisted append-only correction revision or PostgreSQL replay. ## Mainline fixture-correction overlay — 2026-10-14

`FixtureCorrectionHistory.Resolve` applies ordered, in-memory corrections to a generated fixture and returns resolved events with source and correction provenance. It rejects unknown targets, missing/duplicate correction IDs, nonpositive revisions, conflicting replacements at one revision, changes to source event ID/match/sequence/period/elapsed clock/occurrence time, and contradictory goal type/action/outcome. The highest correction revision wins; input fixture objects and event order remain unchanged. Focused tests exercise deterministic replay after a home-goal correction, replacement metadata, same-revision conflicts, latest-revision selection, each preserved identity/time field, unknown targets and inconsistent goal envelopes.

This is a fixture-only projection of correction history. It does not persist corrections, admit canonical revisions, or update the PostgreSQL event/projection/outbox transaction. The correction tests use the first-party generated synthetic fixture, not the unapproved candidate feed. Evidence and exact verification scope are in [the mainline correction restack report](../../evidence/EP04-S05-CORRECTION-RESTACK-2026-10-14.md). The schema v6–v8 migration sequence from main is retained unchanged. Independent exact-head review is complete; Product Owner acceptance remains pending, and this does not complete EP04-S05.
