### Candidate topology implementation note (2026-10-09)
`infra/canonical-dev-topology.bicep` is an isolated, opt-in DEV candidate root. It defaults `deployCanonicalTopology` to `false`; the normal deployment root/pipeline does not reference it. It declares a VNet with separate workload-profiles ACA, PostgreSQL-delegated, and private-endpoint subnets, private DNS zones/links, an Entra-only PostgreSQL Flexible Server/database, and an internal ACA environment with public network access disabled. It also declares Blob, Key Vault and Event Hubs namespace private endpoints and DNS zone groups using explicit subscription/resource-group/name inputs bound to fixed-type Bicep `existing` resource declarations. These declarations avoid accepting opaque, caller-selected resource IDs; they do not prove the target exists or has a private-only network policy. Target owners must still verify the exact targets and policies; this candidate does not modify target services' public access settings. The ACA subnet is dedicated and delegated to `Microsoft.App/environments`; Microsoft documents `/27` as the minimum for workload-profiles environments. All address ranges and the PostgreSQL SKU are caller-supplied; overlap, reserved ranges, capacity, DNS zone ownership, and region SKU availability still need preflight. This root does not declare workloads, managed identities/RBAC, Service Bus private paths, or operational cost controls. It has no direct public-browser path: Front Door Premium with Private Link or an approved ACA topology change is an unresolved, blocking design choice. Blob storage DNS derives from the active cloud environment, but Key Vault and Event Hubs private DNS literals currently scope this candidate to Azure Public; sovereign-cloud support is not claimed. On local candidate commit `a481094bb8476f07bfffefe38f1d5d1db37781d`, Bicep CLI 0.48.1 compiled the canonical, main and demo roots plus DEV/STAGE/PROD and example parameter files, and linted the canonical root. Generated ARM JSON confirmed `deployCanonicalTopology` defaults to `false` and all 19 emitted resources are conditional. The five target-contract unittests and `git diff --check` passed. Outputs were written only to `/private/tmp`; this is syntax/template evidence only, not Azure validation. These are source checks only; no `what-if`, inventory, provisioning, or connectivity validation was run. The candidate does not close this story's acceptance criteria.
