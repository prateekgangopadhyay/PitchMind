## HLD — system responsibility and architectural boundaries
**Workstream:** Azure Platform. **Owning components / intended files:** infra/ / pipelines/ / identity.  
**Architecture pattern:** IaC + managed identity + what-if.  
**Design task unique to this story:** Parameterized secure resource modules; VNet integration and private endpoints; compile and read-only what-if, no apply.

- Honor separation: Domain pure football rules; Application use-case/ports; Infrastructure adapters; thin API; React presentation. Deviations require ADR/diagram update.
- Inputs must be synthetic, versioned, immutable and sourced through the canonical feed/ledger; no match-specific values hardcoded in C# or React. For infra/quality stories, source refs and environment/release artifacts are also versioned.
- Inputs and outputs carry `matchId, canonicalRevision, selectedTime/sequence` whenever football-related; evidence IDs/provenance where making claims. On errors return structured failure, never guess missing facts.
- Public contracts and security/role boundaries: Target Azure HLD; details in [Azure HLD](../../../architecture/06-target-azure-hld.md), [Football LLD](../../../architecture/07-football-analytics-detailed-lld.md), [API](../../../api/API.md) and [Frontend](../../FRONTEND-SCREEN-CONTRACTS.md).
- Failure and scalability design: bounded memory/queue/retries, cancellation, idempotent effects and telemetry. PostgreSQL is source of truth; optional cache or AI failure cannot rewrite match state.

## Local implementation evidence (EP02-S03)
`scripts/validate_infrastructure_profiles.py` provides an offline profile preflight and is wired into local validation and the Azure DevOps infrastructure validation template. It checks that `.bicepparam` and JSON parameter profiles agree, that only DEV enables the network/Key Vault foundation, that optional analytics remain disabled, and that active Bicep source keeps both foundation modules guarded by `environment == 'dev'`. Six Python mutation tests passed, including commented-control and JSON-only STAGE override cases. Bicep CLI 0.48.1 compiled `infra/main.bicep`, the offline demo template, and DEV/STAGE/PROD parameter files. Pipeline YAML parsing, operating-model validation, and `git diff --check` passed. No Azure `what-if`, deployment, or resource mutation was performed. This does not verify deployed private DNS, ACA VNet integration, PostgreSQL connectivity, or owner approval; story acceptance remains open.

**Additional local candidate validation (2026-10-12):** The profile preflight now rejects malformed/non-canonical IPv4 CIDRs, IPv6, and DEV address spaces narrower than `/22`. `/22` is the minimum because `infra/modules/networking.bicep` requests `/24` subnets at indexes 1 and 2. These checks are offline only. They do not prove address-space non-overlap, Azure what-if safety, deployed DNS/connectivity, or Product Owner acceptance.
