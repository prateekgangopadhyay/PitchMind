## LLD — implementable tasks, contracts, state and failure design
1. **Source and schema:** the source-specific C# reader caps input at 64 MiB, validates required raw field shapes, rejects duplicate JSON object keys and source IDs, and requires strictly increasing nonnegative source sequence; it computes SHA-256 and retains every complete input object. The generated [observed data dictionary](../../../data/MANU-LIV-OBSERVED-DATA-DICTIONARY.md) measures structure from the pinned source bytes only. The reader and dictionary do not certify clock, coordinate, period, event, identity, or metric meaning. These semantics and canonical mappings remain blocked pending source-specific evidence and football review.
2. **Use-case and port:** target contracts must retain source event/frame IDs, sequence, raw period/clock, source payload/hash, player/team labels, raw coordinates and nullable source metrics until a reviewed manifest supplies canonical identities, clock policy, pitch units/orientation, metric definitions, and event mappings.
3. **Concrete engineering change:** `ManuLivCandidateFeedReader` is a raw candidate boundary only (`manu-liv-raw-v1`); it is not the canonical anti-corruption mapper and does not emit `EventEnvelope v1` or `TrackingFrame v1`. Coordinate and period normalization to 105x68/metres must not be implemented until declared dimensions and transforms are approved.
4. **Data/persistence semantics:** No match facts in UI/source; mutate canonical event/projection/outbox only in ordered transactional scope if this story writes football state. Read models are revisioned; late corrections create new append-only revision. UI stories query and display, never persist canonical truth.
5. **API/consumer coupling:** Update `docs/api/API.md`, typed .NET/React schema fixtures and selected-time guarantees for any exposed route; reject incompatible fields, unsupported truth classifications and unauthorized users. No direct browser access to Azure secrets or Foundry.
6. **Observability:** correlation ID, source/fixture revision and algorithm version where relevant, sanitized structured event codes, duration/lag/retry outcome metrics; never log secrets or raw copyrighted feed.
7. **Negative/degraded cases:** include unavailable upstream data, malformed input, cancellation, auth denial, replay before evidence and at least one non-happy-path representative of this story.
8. **Environment:** LOCAL Docker or explicitly fake external port; DEV/STAGE/PROD Azure only, never locally emulated services in deployed configuration. No DEV changes before user approval.

### Current v1 contract design
- Wire contracts live in `PitchMind.Contracts.Telemetry.V1`; they do not make the Domain depend on serialization or a provider. JSON Schemas are `schemas/telemetry/v1/event-envelope.schema.json` and `tracking-frame.schema.json`.
- Each envelope carries a schema version, canonical match/event/frame identity and sequence, explicit period/elapsed time, and a `SourceReferenceV1` with original record ID, original sequence, source schema version, source SHA-256, optional UTC source timestamp and distinct provenance/rights-review status.
- For `match_elapsed` clocks with seconds or milliseconds units, the runtime validator checks exact equality against canonical elapsed seconds. `period_elapsed` requires an approved period offset in the source mapper; `provider_defined` is preserved but cannot prove canonical time consistency. Cross-record sequence continuity and same-revision transaction invariants remain store/admission responsibilities and are not certified by per-record validation.
- Event and frame validation returns stable `{code,path,message}` failures for rejection/quarantine. Player-action event types require team/player identity; substitutions also require `relatedPlayerId` while preserving participant direction as an unresolved source mapping. Schema strings reject whitespace-only values and UTC timestamps reject non-zero offsets. Optional event start/end coordinates and tracking positions require declared coordinate units, pitch dimensions, axis origin and per-team attack direction. Pitch dimensions are bounded to 90–120 m by 45–90 m, matching the existing fixture boundary; transforms never infer coordinate semantics and allow elapsed time beyond regulation.
- This v1 vocabulary is a contract vocabulary, not an approved mapping of candidate feed labels. The candidate manifest remains `candidate_not_canonical`; no importer or persistence write is introduced here. Source-specific clock, coordinate, event, team and player mappings remain blocked pending the reviewed manifest and domain/PO evidence.
- The pinned candidate contains a structural period conflict at source sequence 1037: nested `metadata.period="1"`, top-level `period=2`. See the [source profile](../../../data/MANU-LIV-SOURCE-PROFILE.md); neither representation is treated as authoritative.
- Tests use generic synthetic contract values. A normalized coordinate golden checks opposing directions and a half switch; it is not evidence that the candidate JSON uses those semantics.
