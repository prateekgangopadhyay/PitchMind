### Current v1 contract design
- Wire contracts live in `PitchMind.Contracts.Telemetry.V1`; they do not make the Domain depend on serialization or a provider. JSON Schemas are `schemas/telemetry/v1/event-envelope.schema.json` and `tracking-frame.schema.json`.
- Each envelope carries a schema version, canonical match/event/frame identity and sequence, explicit period/elapsed time, and a `SourceReferenceV1` with original record ID, original sequence, source schema version, source SHA-256, optional UTC source timestamp and distinct provenance/rights-review status.
- Event and frame validation returns stable `{code,path,message}` failures for rejection/quarantine. Player-action event types require team/player identity; substitutions also require `relatedPlayerId` while preserving participant direction as an unresolved source mapping. Schema strings reject whitespace-only values and UTC timestamps reject non-zero offsets. Optional event start/end coordinates and tracking positions require declared coordinate units, pitch dimensions, axis origin and per-team attack direction. Pitch dimensions are bounded to 90–120 m by 45–90 m, matching the existing fixture boundary; transforms never infer coordinate semantics and allow elapsed time beyond regulation.
- This v1 vocabulary is a contract vocabulary, not an approved mapping of candidate feed labels. The candidate manifest remains `candidate_not_canonical`; no importer or persistence write is introduced here. Source-specific clock, coordinate, event, team and player mappings remain blocked pending the reviewed manifest and domain/PO evidence.
- Tests use generic synthetic contract values. A normalized coordinate golden checks opposing directions and a half switch; it is not evidence that the candidate JSON uses those semantics.

## Verification plan — executable gate
- **Story-specific tests:** Reject unknown clock, bad coords, missing participant and schema mismatch.
- **Regression scope:** .NET xUnit tests / PostgreSQL isolated integration for backend; frontend Vitest/Playwright/axe for UX; Bicep compile and read-only what-if for platform; red-team and semantic claim checks for AI.
- **Proof fields:** test command and runner, passed/failed/skipped counts, fixture SHA and version, Git commit/digest, API example/HTTP response, accessibility/screenshot evidence as appropriate, security/FinOps review, and owner signature.
- **Authoritative acceptance, unchanged:** Invalid coordinate, period, event-type, missing player or incompatible schema version is rejected/quarantined with reason; valid fixture normalizes consistently for both teams/halves.
- **Release decision:** verification and human PO acceptance required. Any cloud acceptance must use a separately approved change set; implementation or local tests are not DEV authorization.
