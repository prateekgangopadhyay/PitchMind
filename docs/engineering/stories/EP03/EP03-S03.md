## LLD — implementable tasks, contracts, state and failure design
1. **Source and schema:** the candidate file `data/simulations/manu-liv-match-dataset.json` is present and its raw parser validates required source fields, duplicate IDs/properties, increasing source sequence, a 64 MiB input cap, a 100,000-record cap, and exact-byte SHA-256. The record cap bounds per-event metadata and retained raw JSON objects even when source records are very small. Clock units, coordinate units/orientation, player metrics, canonical mappings and football realism remain unverified; owner-confirmed synthetic provenance and redistribution permission do not complete independent rights/privacy review.
2. **Use-case and port:** a LOCAL paced raw replay producer yields parser-produced envelopes in source order, with an inter-record limit of up to 500 records/second within an enumeration. `LocalCandidateFeedReplaySession` adds start, pause, resume, cancel and completion states around that producer. Pause takes effect at a record boundary; an in-flight record is handled and checkpointed before the session reports `Paused`. The consumer acknowledges a record by returning successfully. Its source-bound cursor is then saved before another record is handled. A crash after consumer side effects but before checkpoint replacement can replay that record, so consumers must be idempotent. A new process resumes from the last saved cursor; its first resumed item is immediate, so a strict rate ceiling across process restarts remains unimplemented.
3. **Local checkpoint contract:** `FileCandidateFeedReplayCheckpointStore` stores schema version, feed contract version, exact-byte source SHA-256, next source-record index and last acknowledged source sequence. Reads are bounded to 16 KiB; writes use a same-directory temporary file, flush it, then atomically replace the checkpoint. The adapter rejects reparse points in every existing path component and holds an exclusive file lease so only one replay session can use a checkpoint at a time. Corrupt, oversized, structurally invalid or source-mismatched checkpoints fail closed. Configure the store under a private, trusted local directory: path-based filesystem checks still have a check/use race if another process can mutate its parent directories. The checkpoint is local operational state only; it is not canonical football state or a PostgreSQL/Event Hubs offset.
4. **Remaining adapters:** this slice does not partition to Event Hubs, emit telemetry, map canonical facts, or write PostgreSQL. Event Hubs producer/consumer and Azure partitioning remain future work behind the EP02 cloud foundation.
5. **Concrete engineering change:** Stream validated input using matchId partition key; bounded producer with restartable cursor and source hash.
6. **Data/persistence semantics:** No match facts in UI/source; mutate canonical event/projection/outbox only in ordered transactional scope if this story writes football state. Read models are revisioned; late corrections create new append-only revision. UI stories query and display, never persist canonical truth.
7. **API/consumer coupling:** Update `docs/api/API.md`, typed .NET/React schema fixtures and selected-time guarantees for any exposed route; reject incompatible fields, unsupported truth classifications and unauthorized users. No direct browser access to Azure secrets or Foundry.
8. **Observability:** correlation ID, source/fixture revision and algorithm version where relevant, sanitized structured event codes, duration/lag/retry outcome metrics; never log secrets or raw copyrighted feed.
9. **Negative/degraded cases:** include unavailable upstream data, malformed input, cancellation, auth denial, replay before evidence and at least one non-happy-path representative of this story.
10. **Environment:** LOCAL Docker or explicitly fake external port; DEV/STAGE/PROD Azure only, never locally emulated services in deployed configuration. No DEV changes before user approval.

## Local replay lifecycle and checkpoint slice — 2026-10-15
- Code commit `12ee95b97411b5d7e74efbc4b932285e5b1ca6c7` adds an explicit LOCAL replay-session controller and file checkpoint store. The checkpoint advances only after the consumer returns successfully; the session preserves source event IDs, sequence, raw payload, source hash and parser contract version.
- Pause waits for the current consumer acknowledgement and durable cursor save, then holds before processing the next record. Resume continues that same enumeration. Cancellation during the consumer does not advance the checkpoint. Restart loads the last cursor and the producer rejects another source revision before invoking the consumer.
- The checkpoint file is bounded to 16 KiB on read, schema-versioned and atomically replaced. It rejects reparse points in every existing path component and uses an exclusive session lease. Configure it under a private trusted local directory because path-based checks cannot close a hostile concurrent path-swap race. Consumers must tolerate at-least-once replay if the process fails after side effects but before the checkpoint is replaced.
