### Additive evidence graph contract refinement (PR #39)
- The graph and every event/frame/metric/claim node carry `sourceSha256`, validated as lowercase SHA-256; every node hash must equal the graph hash. In the current offline path, the hash identifies the exact serialized synthetic fixture. A canonical adapter must use the registered raw-source hash. `sourceVersion` remains the schema/fixture version and `provenance` remains the source class.
- Claim truth labels are `fact`, `derivation`, `pattern`, `interpretation`, and `hypothesis`. Source event/frame nodes are `fact` only within their declared provenance; a synthetic fact is not a claim that a real match event occurred. Unsupported conclusions are rejected rather than assigned a publishable truth class, and hypotheses cannot be published as supported claims.
- Graph conditions are typed as `{id, passed, observed, threshold, sourceNodeIds, exclusionReason}`. Failed evaluations require an exclusion reason and every source node ID must resolve. `uncertainty` says no confidence score is available for the uncalibrated demo; no confidence value is invented. Detector paths that suppress a candidate still need negative tests; the current response does not expose a diagnostic graph for suppressed candidates.
- The fields are additive to v1 JSON. Existing consumers can ignore unknown properties; consumers that display evidence should bind to the graph/node `sourceSha256` and keep source version and provenance separate.
