## LLD — implementable tasks, contracts, state and failure design
1. **Source and schema:** the read path consumes only validated `TrackingFrameV1` records already persisted in PostgreSQL. It bounds payload/quality sizes and verifies frame IDs, sequence, period, selected match time and source hash against indexed metadata. The candidate synthetic JSON is not read or mapped here; its coordinate units, player metrics, realism and canonical mappings remain subject to source admission review.
2. **Use-case and port:** `IMatchTrackingReader` returns frames for one exact selected second at or below the selected projection sequence watermark. The React pitch requires declared pitch dimensions, units, origin and team directions. It provides event buttons, a time scrubber and play/pause; missing frame samples stay empty and are never interpolated. The accessible table exposes the recorded player IDs, team IDs and view-oriented metre coordinates.
3. **Concrete engineering change:** SVG pitch renders only observed data; the frame-declared team direction establishes the reference orientation, and the frame period/time remain visible. Numbered markers correspond to an open position table. Timeline event selection and scrub select exact recorded times; play/pause advances the selected time without interpolating positions.
4. **Data/persistence semantics:** No match facts in UI/source; mutate canonical event/projection/outbox only in ordered transactional scope if this story writes football state. Read models are revisioned; late corrections create new append-only revision. UI stories query and display, never persist canonical truth.
5. **API/consumer coupling:** Update `docs/api/API.md`, typed .NET/React schema fixtures and selected-time guarantees for any exposed route; reject incompatible fields, unsupported truth classifications and unauthorized users. No direct browser access to Azure secrets or Foundry.
6. **Observability:** correlation ID, source/fixture revision and algorithm version where relevant, sanitized structured event codes, duration/lag/retry outcome metrics; never log secrets or raw copyrighted feed.
7. **Negative/degraded cases:** empty frame pages produce an explicit no-observation message; a frame API 503 does not fall back to demo data; malformed persisted frame content is rejected as a typed 503; frame pages with the wrong match, time, revision, watermark, sequence or source identity fail closed and no frame is drawn. PostgreSQL execution evidence requires an isolated local `PITCHMIND_TEST_POSTGRES` database.
8. **Environment:** LOCAL Docker or explicitly fake external port; DEV/STAGE/PROD Azure only, never locally emulated services in deployed configuration. No DEV changes before user approval.
