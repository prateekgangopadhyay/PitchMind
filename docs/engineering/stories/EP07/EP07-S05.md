**Design task unique to this story:** Evidence drawer resolves typed event/frame/metric refs, persisted condition vector and limitations; mechanism replay navigable. The current canonical response carries bounded stored conditions and nullable stored limitations; metric references remain unavailable until a canonical metric payload store exists.

- Honor separation: Domain pure football rules; Application use-case/ports; Infrastructure adapters; thin API; React presentation. Deviations require ADR/diagram update.

## LLD — implementable tasks, contracts, state and failure design
1. **Source and schema:** identify exact input fields/source adapter and validate field presence/type/size/clock/coordinate and source hash; classify missing data explicitly. Canonical insight reads preserve the persisted `conditions_json` object and nullable `limitations_json` list with explicit bounds.
2. **Use-case and port:** Progressive disclosure: narrative → Why? → source events/timestamps → pitch overlay → metrics/advanced definition; repeatable tactical mechanism replay with highlighted participants and observed sequence.
3. **Concrete engineering change:** Evidence drawer resolves typed event/frame/metric refs, condition vector and limitations; mechanism replay navigable.
4. **Data/persistence semantics:** No match facts in UI/source; mutate canonical event/projection/outbox only in ordered transactional scope if this story writes football state. Read models are revisioned; late corrections create new append-only revision. UI stories query and display, never persist canonical truth.
5. **API/consumer coupling:** `CanonicalInsight` carries bounded stored conditions and nullable limitations on list, detail and evidence routes; the frontend verifies these values against the selected insight before disclosure. No direct browser access to Azure secrets or Foundry.
6. **Observability:** correlation ID, source/fixture revision and algorithm version where relevant, sanitized structured event codes, duration/lag/retry outcome metrics; never log secrets or raw copyrighted feed.
7. **Negative/degraded cases:** include unavailable upstream data, malformed input, cancellation, auth denial, replay before evidence and at least one non-happy-path representative of this story. Null limitations are described as unrecorded metadata, not proof that limitations do not exist.
8. **Environment:** LOCAL Docker or explicitly fake external port; DEV/STAGE/PROD Azure only, never locally emulated services in deployed configuration. No DEV changes before user approval.

**Local source navigation:** The canonical evidence response contains event/frame source IDs, sequence, match clock, period and payload. Link those supported sources to the existing selected-time replay route using the source clock and insight revision; the event sequence or frame sequence is the fragment target. Replay focuses the matching target after canonical data loads. If the selected-time frame page omits the referenced frame, keep positions absent and report that source unavailable. The current canonical read API exposes no metric source route, so metric references must not receive a guessed link. Focused Vitest coverage verifies event/frame URL context and that a frame link selects and focuses the exact recorded frame when several frames share the same second.
