## HLD — system responsibility and architectural boundaries
**Workstream:** API & Realtime. **Owning components / intended files:** Contracts + Api + SignalR adapters.  
**Architecture pattern:** versioned BFF read model + live cursor.  
**Design task unique to this story:** Implement typed BFF endpoints via Application query ports, cursor-pagination, selected-time revision, RFC7807 errors.

- Honor separation: Domain pure football rules; Application use-case/ports; Infrastructure adapters; thin API; React presentation. Deviations require ADR/diagram update.
- Inputs must be synthetic, versioned, immutable and sourced through the canonical feed/ledger; no match-specific values hardcoded in C# or React. For infra/quality stories, source refs and environment/release artifacts are also versioned.
- Inputs and outputs carry `matchId, canonicalRevision, selectedTime/sequence` whenever football-related; evidence IDs/provenance where making claims. On errors return structured failure, never guess missing facts.
- Public contracts and security/role boundaries: Consolidated API; details in [Azure HLD](../../../architecture/06-target-azure-hld.md), [Football LLD](../../../architecture/07-football-analytics-detailed-lld.md), [API](../../../api/API.md) and [Frontend](../../FRONTEND-SCREEN-CONTRACTS.md).
- Failure and scalability design: bounded memory/queue/retries, cancellation, idempotent effects and telemetry. PostgreSQL is source of truth; optional cache or AI failure cannot rewrite match state.

## LLD — implementable tasks, contracts, state and failure design
1. **Source and schema:** canonical routes read only immutable PostgreSQL projections, ordered ledger events, and persisted insight/evidence references. The candidate Manchester United–Liverpool feed is present but is not canonicalized or projected; no BFF route falls back to it or to the offline demo. The offline demo remains separately namespaced by its existing routes.
2. **Use-case and port:** `IMatchProjectionReader` owns selected-time/revision reads and bounded event pages; `IMatchInsightReader` owns persisted insight/evidence reads. Infrastructure uses PostgreSQL; when no canonical adapter is configured, routes return a typed 503 rather than demo data.
3. **Concrete endpoint contract:** `GET /api/v1/canonical/fixtures?afterMatchId&limit` returns latest persisted projection cards. `GET /api/v1/canonical/matches/{matchId}/summary?atSeconds&revision` returns the exact selected-time projection with canonical revision, state/source hashes and provenance. `/events` pages ledger entries; `/insights` pages persisted insights only when every event/frame reference is visible both at the selected time/sequence and no later than the insight's own `as_of_sequence`; insight responses include source version, provenance and the source hash for the insight's canonical revision. `/insights/{insightId}` returns one such insight; `/evidence/{insightId}` returns complete event/frame payloads under both time bounds; `/replay` composes the same snapshot and event page. Event and insight cursors bind match, selected time and canonical revision. Page size is 1..100. `atSeconds` is 0..5400, default 0, and every page reports the selected time and revision.
4. **Key moment behavior:** `/api/v1/canonical/matches/{matchId}/key-moments` currently returns `503 CANONICAL_KEY_MOMENTS_UNAVAILABLE`. The database has no persisted key-moment projection, and converting simulated fixture moments into canonical data would be false. The existing fixture-backed key-moment route remains a synthetic demo and is not a fallback.
5. **Errors and security:** malformed GUIDs, times, revisions, limits and context-mismatched cursors receive typed 400 responses; missing selected-time state/insight receives 404; an absent/unavailable database receives sanitized 503. Authentication/authorization is an EP06-S04 gate; these routes must not be exposed in a cloud deployment until that boundary is implemented or an explicit synthetic public-read boundary is approved.
6. **Data/persistence semantics:** No match facts in UI/source; mutate canonical event/projection/outbox only in ordered transactional scope if this story writes football state. Read models are revisioned; late corrections create new append-only revision. UI stories query and display, never persist canonical truth.
6. **API/consumer coupling:** Update `docs/api/API.md`, `docs/api/openapi-canonical-bff-v1.yaml`, typed .NET and React schema fixtures and selected-time guarantees for any exposed route; reject incompatible fields, unsupported truth classifications and unauthorized users. No direct browser access to Azure secrets or Foundry.
7. **Observability:** correlation ID, source/fixture revision and algorithm version where relevant, sanitized structured event codes, duration/lag/retry outcome metrics; never log secrets or raw copyrighted feed.
8. **Negative/degraded cases:** include unavailable canonical adapter, malformed cursor/ID/time, cancellation, auth boundary handoff, replay before first projection, missing evidence reference, and a later event/insight/frame excluded from an earlier selected time and sequence.
9. **Environment:** LOCAL Docker PostgreSQL or an explicit unavailable adapter; DEV/STAGE/PROD Azure services only, never locally emulated services in deployed configuration. No DEV changes before user approval.
