## Local implementation slice (partial; not story acceptance)
The draft implementation adds `GET /api/v1/canonical/matches/{matchId}/timeline/backfill?afterSequence&atSeconds&revision&limit`. The response binds the selected-time snapshot and ordered event page to one canonical projection. The `revision` query guard carries `projectionRevision` (distinct from the 64-bit `canonicalRevision`) because the endpoint compares it with the durable projection revision. A projection-revision change or a cursor ahead of the durable projection sets `replayRequired` and reads again from sequence -1; same-revision pages continue from the client's last applied sequence. Page size is bounded to 1..100 and PostgreSQL remains the only source for returned football facts.

In LOCAL Development with `Runtime:Profile=local`, explicit `Realtime:Provider=local`, and a single PostgreSQL loopback host, the EP06-S02 API host starts `OutboxDispatchWorker` using the existing PostgreSQL lease/retry adapter. It publishes cursor-only messages for committed projection outbox rows; it does not synthesize source events or alter canonical state. Azure profiles and remote/multi-host database configurations do not register this local dispatcher.

The typed React reducer handles duplicate pages idempotently, rejects conflicting event IDs/sequences and future events, detects gaps, and preserves the selected timestamp when cursor notifications arrive in HISTORICAL mode. Switching time contexts requests a full event replay from sequence -1; applying that page replaces the old timeline and snapshot with the returned selected-time projection so live events and score cannot leak into an earlier view. Stale backfill responses for a different selected time are rejected. `fetchTimelineBackfill` selects the canonical head only in LIVE mode and uses the exact selected time in HISTORICAL mode. The current App does not yet connect this reducer to a browser SignalR client: the stacked base lacks a production authentication scheme and a SignalR browser package, and the canonical feed producer is not yet wired. Therefore the full two-browser disconnect/reconnect journey and nonintrusive new-insight UI indicator remain blocked; this slice is not acceptance.
